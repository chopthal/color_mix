# 에이전트 워크플로 (역할·배정·위임·감사 SSOT)

> 상시 규칙은 `AGENTS.md`. 이 문서는 **역할·워커 배정·위임·감사·검증 기준의 단일 출처**다.
> 모델 배정표는 이 문서 §2에만 둔다. 진입 파일(`CLAUDE.md`·`GEMINI.md`·`.cursor/`)에는 표를 중복 기재하지 않는다.

## 1. 역할

| 역할 | 담당 | 하는 일 |
| :--- | :--- | :--- |
| **오케스트레이터** | Claude Opus 5.5 (effort medium) — 모든 세션 시작점 | 요구 정리 → 읽기 조사 → 작업 분해·워커 배정안(착수 게이트) → 브리프 작성·`delegate_task` 위임 → 감사(diff 직접 리뷰 + 검증 재실행) → 사용자 테스트 시나리오 → 지시 시 커밋·PR |
| **1순위 워커** | antigravity · gemini-3.8-flash (thinking_level low/medium/high) | 브리프 범위 구현 |
| **상위 워커** | antigravity · gemini-4-argon | Flash로 위험하거나 감사 불통 시 |
| **Claude 워커** | Opus 5.5 / Fable 5.2 | 착수 게이트에 `참고: <모델>(<effort>) — 이유`로 제안 → 사용자 승인 시만 투입 (특수 티어는 기본 제안) |
| **명시 전용** | Cursor, OpenCode·DeepSeek(deepseek-v4-pro, deepseek-v4.1-flash) | 사용자가 워커로 지명할 때만 |

**Claude 워커 effort 기준** (max·Opus low 미사용, Fable 단가 ≈ Opus의 2배)

- Opus medium: 명세 분명한 구현·감사
- Opus high: 권한·보안·여러 파일 정합성
- Opus xhigh: high로 못 풀었을 때만
- Fable high: Opus로 못 푼 원인 불명·대규모 재설계 시작점
- Fable xhigh: Fable high로 못 풀었을 때만

**오케스트레이터 직접 수정 허용:** ① 거버넌스 문서 ② 감사에서 나온 1~3줄 수정 ③ 사용자가 직접 지시한 경우(§3 초소형 승인 포함). 그 외 구현은 위임한다.

## 2. 워커 배정표 (SSOT)

착수 게이트 형식: **`[난이도 / 워커: <제공자·모델(레벨)>]` + 이유 1줄** (Claude 워커는 `참고:`로 병기)

| 티어 | 기준 (이 레포 맥락) | 기본 워커 | 참고 (Claude, 승인 시) |
| :--- | :--- | :--- | :--- |
| **하** | 문서·문구·CSS·오탈자 | Flash low | — |
| **중** | 명세 분명한 단일 게임 인터랙션·사운드 합성·CSS 모션 | Flash medium | — |
| **상** | 다수 게임 결합·캔버스 물리·상태머신 전면 개편 | Flash high (위험하면 Argon high) | Opus 5.5(medium) |
| **특수** | 권한·보안·원인 불명 버그·계약 파괴 위험 (파일 수 무관 격상) | **Claude Opus 5.5(high)** | 대안: Argon high / 막히면 Fable 5.2(high) |

- 티어 = 범위·모호성·위험도 (모델 서열 아님)

## 3. 작업 모드 (가벼운 모드 기본)

위험이 낮은 정적 게임 레포이므로 작은 작업에 전체 절차를 돌리지 않는다. **위로 갈수록 우선 판정.**

| 모드 | 기준 | 절차 |
| :--- | :--- | :--- |
| **초소형** | 파일 1개 · 3줄 이하 · 분기/상태 로직 변화 없음 (오탈자, CSS 값 1개, 확정 원고 반영) | 게이트 1줄(`[하 / 직접]`) → 승인 → 오케스트레이터 직접 수정 → `node --check`(JS일 때) |
| **가벼운** | 하·중 · 게임 폴더 1개 내부 · `index.html` 로비·공용 자산·§6 카피 무관 | 짧은 브리프(템플릿 D-lite: 목표·파일·완료 조건·검증) → 바로 위임 → 감사(diff + 검증 재실행) |
| **표준** | 상·특수, 또는 로비·여러 게임·공용 파일을 건드림 | 전체 브리프(템플릿 D) → 위임 → 감사 + UI preview 확인 |

- **병렬 위임은 기본 미사용.** 직렬 위임이 이 레포 규모에서 토큰·안정성 모두 유리하다.
  - 예외: 서로 독립된 게임 폴더 작업 2개 이상 + 사용자 명시 시에만. 워커별 소유 파일 겹침 0%, 공용 로비(`index.html`)·`STATUS.md`는 오케스트레이터만 통합 시 수정, 워커별 단독 `node --check`, 통합 후 오케스트레이터가 전역 검증 1회.
- 위임 중 오케스트레이터는 같은 워킹트리를 동시에 수정하지 않는다(직렬 핸드오프).

## 4. 감사·에스컬레이션

- 워커의 PASS 보고를 믿지 않는다. 오케스트레이터가 `git diff`를 직접 읽고 §7 검증을 **다시 실행**한다.
- 감사 항목: 범위 이탈·파일 경계 / 요구 누락 / 임시·미사용 코드 / 만 4세 가드레일(§6) 위반.
- 감사 1~3줄 수정은 오케스트레이터가 직접, 그보다 크면 같은 워커에 재위임.
- **같은 작업이 감사를 2회 통과 못 하면** 상위 워커(Flash → Argon high → Claude 참고 Opus high / Fable high)를 사용자에게 제안한다.

## 5. 워커 모드 조항

오케스트레이터에게 위임받은 하위 작업이면:

1. **브리프가 곧 착수 승인** — 컨펌 대기 없이 범위 안만 구현
2. 범위 밖 발견은 고치지 말고 보고만
3. `git commit`·`push`·PR·브랜치 전환·stash·`STATUS.md` 수정 금지
4. 마지막 보고: 변경 파일 / 검증 명령·결과 / 범위 밖 발견

사용자가 직접 연 세션(위임 아님)이면 `AGENTS.md` 착수 게이트를 그대로 따른다.

## 6. 도메인 금지·기록

- 만 4세 가드레일·인게임 페르소나·기획 카피(`docs/PROJECT.md` §6): 위임이든 직접이든 에이전트 창작·변경 금지. 브리프에도 창작 지시를 넣지 않는다(확정 원고의 기계적 반영만).
- 새 게임·큰 개편: `docs/PROJECT.md` §8 + `docs/games/_template.md` 합의 전 착수 금지.
- "앞으로 ~하겠다" 약속 대신, 중요한 교훈은 그 자리에서 해당 문서에 기록한다. 중요도가 낮으면 문서를 늘리지 않는다.

## 7. 검증 기준

- **기본:** 변경한 JS 전부 `node --check <파일>` + 콘솔 오류 0건 확인.
- **UI 확인:** T3 내장 `preview_*`(모바일 폭 preset) 1순위. 불가 시 `npx --yes serve . -p 4173` + 브라우저 개발자도구 모바일 에뮬레이션. 터치 타깃 48px+·가로/세로 깨짐을 본다.
