# Agent 프롬프트 템플릿

사용자가 이 파일을 열지 않아도 된다. 에이전트가 작업 시작 시 읽고 A/B/C/D/D-lite를 적용한다.

원칙 SSOT: `AGENTS.md`. 작업 모드(어느 브리프를 쓸지): `docs/workflow.md` §3.

## A. 기능 구현 (기본)

```text
[구현]
STATUS「다음」만. 기존 구조 확인 후 최소 수정만.
새 추상화·라이브러리·범위 밖 리팩터 금지. 모호하면 구현 전 선택지 2~3개.
완료 조건: (아래) + 관련 검증을 실제로 실행한 뒤에만 완료 보고.
끝에: 변경 파일 / 돌린 명령·결과 / 기존 기능 영향 가능성.

목표:
범위(만질 곳 / 만지지 말 곳):
성공 기준:
이번 요청:
```

## B. 감사 only (코드 변경 금지)

```text
[감사 only]
기능을 추가·수정하지 마라. 품질·유지보수·운영 위험만 분석.
스타일 취향과 실결함을 구분. 근거 없는 전면 재작성 제안 금지.

검토:
1) 핵심 흐름이 docs/PROJECT.md·계약과 맞는지
2) 중복·불필요 추상화·과도 복잡성(근거 있는 것만)
3) 예외 은폐·테스트 공백이 있는 핵심 경로
4) 보안·시크릿·인증·권한
5) 불필요 의존성·배포 위험
6) 앞으로 수정 범위가 과도해질 경계
7) 만 3~5세 UX·인게임 가드레일 위반 가능성

발견마다: 경로·근거·영향·심각도·수정 필요 여부·권장 방향·수정 전후 확인 방법.
코드는 변경하지 말고 보고만.

이번 감사 초점:
```

```text
성공 기준:
```

## D. 위임 브리프 — 표준 (상·특수, 로비·여러 게임·공용 파일)

오케스트레이터가 `delegate_task` 등으로 워커에게 넘길 때 사용. 워커는 `docs/workflow.md` §5 워커 모드로 수행한다.

**작성 규칙**

- 판단 지점(방식 선택·값·이름)은 오케스트레이터가 미리 결정해 적는다. 워커에게 고르게 하지 않는다.
- 수정 대상 줄을 검색으로 뽑을 때 출력을 잘라 보지 않는다(`cut`·`head` 금지). 전체 결과를 확인한 뒤 `파일:줄`로 적는다.
- 만 4세 가드레일·페르소나·기획 카피(`docs/PROJECT.md` §6) 창작 지시 금지. 확정 원고는 원문 그대로 붙인다.

```text
[위임 · 워커 모드: docs/workflow.md §5 — 브리프가 곧 착수 승인, 커밋·푸시·PR·STATUS 수정 금지]

목표:
배경·근거 (파일:줄):
수정 범위 (이 파일만):
만지지 말 곳:
구체 지시 (판단 지점은 결정 완료):
  1.
완료 조건:
검증 명령:
  - node --check <변경 JS>
보고 형식: 변경 파일 / 검증 명령·결과 / 범위 밖 발견(수정하지 말고 보고만)
```
