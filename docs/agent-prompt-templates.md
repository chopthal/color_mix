# Agent 프롬프트 템플릿

사용자가 이 파일을 열지 않아도 된다. 에이전트가 작업 시작 시 읽고 A/B/C/D를 적용한다.

원칙 SSOT: `AGENTS.md`.

## A. 기능 구현 (기본)

```text
[구현]
STATUS「다음」만. 기존 구조 확인 후 최소 수정만.
새 추상화·라이브러리·범위 밖 리팩터 금지. 모호하면 구현 전 선택지 2~3개.
완료 조건: (아래) + 관련 검증을 실제로 실행한 뒤에만 완료 보고.
끝에: 변경 파일 / 돌린 명령·결과 / 기존 기능 영향 가능성.

목표:
범위(만질 곳 / 만지지 말 곳):
성공 기준:
이번 요청:
```

## B. 감사 only (코드 변경 금지)

```text
[감사 only]
기능을 추가·수정하지 마라. 품질·유지보수·운영 위험만 분석.
스타일 취향과 실결함을 구분. 근거 없는 전면 재작성 제안 금지.

검토:
1) 핵심 흐름이 docs/PROJECT.md·계약과 맞는지
2) 중복·불필요 추상화·과도 복잡성(근거 있는 것만)
3) 예외 은폐·테스트 공백이 있는 핵심 경로
4) 보안·시크릿·인증·권한
5) 불필요 의존성·배포 위험
6) 앞으로 수정 범위가 과도해질 경계
7) 만 3~5세 UX·인게임 가드레일 위반 가능성

발견마다: 경로·근거·영향·심각도·수정 필요 여부·권장 방향·수정 전후 확인 방법.
코드는 변경하지 말고 보고만.

이번 감사 초점:
```

## C. 단순화 (증거 있을 때만)

```text
[단순화]
동작 동일 전제. 합의된 범위만.
미사용·중복이 근거로 확인된 것만 제거·통합.
새 패턴·대규모 rename 금지.
완료 전: 관련 확인(파일·필요 시 serve) 실행 및 로그 제시.

범위·근거:
성공 기준:
```

## D. 하위 워커 표준 지시문 (서브에이전트 / 위임 워커)

지휘 에이전트(Orchestrator)가 서브에이전트 또는 위임 작업(delegate_task 등)을 구동할 때 사용하는 템플릿.

```text
당신은 [역할명] 전문 워커(Worker N)입니다.
반드시 아래 할당된 본인의 소유 파일만 수정하고, 다른 파일이나 공용 로비는 절대 건드리지 마세요.
커밋(git commit), 푸시(git push), 공유 상태 문서(STATUS.md) 수정은 절대 하지 마세요.

[소유 파일 (이 파일 외 수정 금지)]
- games/<게임명>/index.html
- games/<게임명>/css/style.css
- games/<게임명>/js/game.js
- docs/games/<게임명>.md

[담당 작업]
1. docs/PROJECT.md의 만 4세 UX 원칙(No Penalty, 48px+ 터치, 텍스트 최소화) 준수
2. 순수 정적 웹(HTML5/CSS3/Vanilla JS, Web Audio API 합성) 구현
3. ...

[단독 검증 명령]
- node --check games/<게임명>/js/game.js

작업 완료 후 수정한 파일 내역과 단독 검증 결과를 요약해 메인 지휘 에이전트에게 보고하세요.
```
